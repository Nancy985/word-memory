## 【项目介绍 · 1 分钟】

### 要解决什么问题？

传统背单词有两个痛点：
1. **不知道什么时候开始复习**，容易背了忘、忘了背；
2. **缺少自测和错词追踪**，不知道自己 weak 在哪里。

### 我们的方案

| 功能 | 说明 |
|------|------|
| 用户登录注册 | Token 鉴权，密码 BCrypt 加密 |
| 单词书管理 | 创建单词书，支持 **CSV 批量导入** 单词 |
| 艾宾浩斯背单词 | 按记忆曲线自动安排复习时间 |
| 四选一自测 | 自动生成题目并计分 |
| 错词统计 | 答错自动记录，方便重点复习 |
| 考试记录 | 保存历史成绩和答题明细 |

---

## 【技术架构 · 1 分钟】

我们采用 **前后端分离** 架构：

```
浏览器（前端页面）
    ↓  HTTP + JSON
Spring Boot 后端（端口 3500）
    ↓  JPA
H2 数据库（7 张表）
```

**后端分层：**
- **Controller** — 接收请求，返回统一 JSON
- **Service** — 业务逻辑（艾宾浩斯算法、出题计分）
- **Repository** — 数据库操作
- **Entity** — 对应 7 张数据表

**为什么这样设计？**  
职责清晰，改业务逻辑不影响接口层，方便维护和联调。

---

## 【核心亮点 · 1.5 分钟】（重点背）

### 亮点一：艾宾浩斯间隔复习算法

这是项目最大的技术亮点。

**原理：** 根据遗忘曲线，答对单词后复习间隔逐渐延长：

> 5分钟 → 30分钟 → 12小时 → 1天 → 2天 → 4天 → 7天 → 15天 → 30天

- **答对** → 进入下一阶段，间隔变长  
- **答错** → 重置到第一阶段（5 分钟），并记入错词本  

**代码位置：** `SpacedRepetitionUtil.java`  
**可视化：** 背单词页面顶部有记忆曲线图，调用 `/api/memorize/curve` 接口展示各阶段单词分布。

答辩时可以打开这个文件指给老师看。

### 亮点二：CSV 批量导入单词

支持用户粘贴 CSV 文本批量导入，格式：`单词,音标,释义,例句`  
后端接口：`POST /api/wordbooks/{id}/words/import`  
自动跳过重复单词，返回导入成功/失败数量。

### 亮点三：统一 API 规范

- 所有接口返回统一格式：`{ code, message, data, timestamp }`
- Token 鉴权：登录后获取 token，后续请求携带 `Authorization: Bearer xxx`
- 接口文档在 **Apifox**，每个接口录了成功/失败案例，方便联调

# 附：老师常问问题 · 简答版

### Q1：你的分工是什么？
> 我负责后端全部 API 开发、数据库设计、Apifox 接口文档和联调。前端是 AI 辅助生成的，我保证接口稳定可用。

### Q2：艾宾浩斯算法怎么实现的？
> 在 SpacedRepetitionUtil 里定义 9 级复习间隔。用户答对，reviewStage 加 1，按间隔算 nextReviewAt；答错则 stage 归零，5 分钟后复习，同时写入错词表。

### Q3：前后端怎么联调的？
> 先在 Apifox 定义接口文档，后端实现后逐个测试。前端按文档调 API，登录拿 Token，后续请求带 Authorization 头。联调时走完整流程：登录→单词书→背单词→自测→记录。

### Q4：为什么用 Spring Boot + JPA？
> Spring Boot 快速搭建 REST 后端；JPA 用 Java 类映射数据库表，减少手写 SQL；H2 内存数据库方便开发演示，生产可换 MySQL。

### Q5：Token 和 Session 有什么区别？
> Session 存在服务端，适合传统网页。Token 无状态，存在客户端，适合前后端分离，我们的前端每次请求带 Token，后端拦截器验证。

### Q6：什么是 RESTful？
> 用 URL 表示资源，用 HTTP 方法表示操作：GET 查询、POST 新增、PUT 修改、DELETE 删除，前后端传 JSON。

### Q7：Git 分支怎么管理的？
> main 放稳定版，develop 日常开发，新功能从 develop 拉 feature 分支，完成后 merge 回 develop，合并用 --no-ff 保留历史。

### Q8：如果单词答错了会怎样？
> reviewStage 重置为 0，nextReviewAt 设为 5 分钟后，同时在 wrong_word_records 表记录错词，错词页面可以查看。

### Q9：数据库有几张表？分别存什么？
> 7 张：users 用户、word_books 单词书、words 单词、user_word_progress 复习进度、wrong_word_records 错词、exam_records 考试记录、exam_answers 答题明细。

### Q10：项目还有什么可以改进的？
> 可以接 MySQL 持久化、加 Redis 缓存 Token、支持单词语音朗读、Excel 文件导入、移动端适配等。
