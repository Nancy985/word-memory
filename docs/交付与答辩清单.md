## 四、Apifox 必做清单（后端重点）

在 Apifox 创建项目「词忆 word-memory」，Base URL：`http://localhost:3500`

每个接口至少保存 **3 条案例**：

| 接口 | 成功案例 | 失败案例 | 异常案例 |
|------|---------|---------|---------|
| POST /api/auth/login | demo 登录成功 | 密码错误 | 用户名为空 |
| POST /api/auth/register | 注册新用户 | 用户名已存在 | 密码少于6位 |
| GET /api/wordbooks | 返回单词书列表 | 未带 Token 401 | — |
| GET /api/memorize/today | 返回待复习单词 | wordBookId 不存在 | 未登录 |
| POST /api/memorize/review | correct=true | wordId 不存在 | 参数缺失 |
| POST /api/quiz/generate | 生成10道题 | 单词不足4个 | count 超范围 |
| POST /api/quiz/submit | 提交并返回分数 | 答案为空 | wordId 不属于该书 |
| GET /api/wrong-words/stats | 返回统计 | 未登录 | — |
| GET /api/exams | 返回记录列表 | 未登录 | — |

> **转正底线：** 即使前端进度慢，Apifox 全部接口能跑通 + 案例齐全。

## 七、答辩亮点（必须能说出来）

| 亮点 | 一句话怎么说 | 对应代码/文件 |
|------|-------------|--------------|
| 艾宾浩斯间隔复习 | 根据记忆曲线自动安排复习时间，答对升级、答错重置 | `SpacedRepetitionUtil.java` |
| 前后端分离 + 统一响应 | 后端 REST API，统一 JSON 格式 `{code, message, data}` | `ApiResponse.java` |
| 完整分层架构 | Entity → Repository → Service → Controller | `src/main/java/com/wordmemory/` |
| Token 鉴权 | 登录获 token，拦截器校验，无 token 返回 401 | `AuthInterceptor.java` |
| 四选一自测 | 自动生成干扰项，提交后更新复习进度和考试记录 | `QuizService.java` |
| 错词追踪 | 答错自动记入错词本，支持统计分析 | `WrongWordService.java` |
| 绿色系前端 | 暖白 + 绿色主题，单页应用，无需 npm 构建 | `static/index.html` |

答辩可能被问的基础题：
- Git 分支管理（main / develop / feature）
- Git 提交规范（feat / fix / docs）
- 前后端如何联调（Apifox + Token）
- RESTful 是什么
- JPA 和数据库的关系
- 什么是跨域，本项目怎么解决的
